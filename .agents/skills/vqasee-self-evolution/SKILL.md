# VQASee 自闭环 / 自我进化

## 使命

让 VQASee 每次使用、测试、失败、反馈之后，都能变得更好。不要只修一个点；要把经验沉淀为：

1. 产品原则；
2. 测试用例；
3. prompt/模型规则；
4. UI 状态和文案；
5. 系统监控指标；
6. 下一轮路线图。

最终目标：VQASee 像 iPhone 一样，越来越简单、可靠、自然、值得信任。

## 工作方式

每次触发本 skill，按下面闭环执行：

```text
观察 → 归因 → 排序 → 实验 → 验证 → 沉淀 → 下一轮
```

## 1. 观察：收集事实

先区分事实和猜测。

优先收集：

- 用户原话；
- 场景：室内/室外/走路/读文字/问问题/网络切换；
- 当前模式：行走/周围/详细/读文字；
- 失败表现：慢、错、啰嗦、没播报、误播报、连接失败、UI 看不懂；
- 可量化数据：端到端延迟、模型耗时、timeout、重连次数、speech gate 是否抑制；
- 相关文件：iOS、backend、relay、prompt、测试。

如果没有数据，不要假装确定。明确标注：

```text
已知事实：...
合理猜测：...
需要验证：...
```

## 2. 归因：四角色分析

必须用四个角色分别分析：

### 乔布斯：产品归因

判断这个问题是否影响 VQASee 的核心价值：

- 用户是否因此不敢用？
- 是否增加了学习成本？
- 是否破坏“拿起就用”？
- 是否让产品显得像 demo 而不是工具？

### 罗根：系统归因

判断问题是否来自架构、性能、状态机或可靠性：

- 是否有 timeout/retry/reconnect 缺口？
- 是否有帧队列、并发、阻塞问题？
- 是否有日志缺失？
- 是否可以复现？

### 思余：UI 归因

判断问题是否来自界面和交互：

- 状态是否明确？
- 用户是否知道下一步做什么？
- 文案是否技术化？
- 是否适合低视力/VoiceOver/Dynamic Type？

### 全麦：模型归因

判断问题是否来自 prompt、模型、schema 或后端：

- 模型是否理解当前模式？
- 输出是否过长、过慢、不稳定？
- 是否遗漏安全信息？
- 是否缺测试样例？

## 3. 排序：决定下一步先做什么

按下面顺序排序：

1. 安全风险；
2. 用户能否完成核心任务；
3. 延迟和稳定性；
4. 易用性和美观；
5. 工程便利性。

输出优先级时使用：

```text
P0：不修不能用或有安全风险
P1：影响核心体验
P2：明显改善体验
P3：锦上添花
```

## 4. 实验：提出最小改动

不要一上来大重构。优先提出最小实验：

- 一条 prompt 修改；
- 一个 UI 状态文案；
- 一个 timeout/reconnect 修复；
- 一个 latency log；
- 一个测试用例；
- 一个模式参数调整。

每个实验必须写清：

```text
假设：如果我们做 X，Y 指标会改善。
改动：最小需要改哪些文件。
验证：跑什么测试，或如何人工测试。
成功标准：达到什么结果才算有效。
失败处理：如果无效，下一步怎么退回/调整。
```

## 5. 验证：不通过不算进化

能跑测试就跑测试。常用命令：

```bash
source .venv/bin/activate && pytest server-vqa/tests
source .venv/bin/activate && pytest relay-server/tests
bash deploy/ios/test.sh
```

如果不能跑，明确说明原因，并给出人工验证步骤。

## 6. 沉淀：把经验写回系统

每次闭环结束，判断是否需要更新：

- `AGENTS.md`：长期项目规则；
- `docs/vqasee-codex-agent-design.md`：团队协作方式；
- 相关 skill：工作流本身需要进化；
- 测试文件：把 bug 变成回归测试；
- README/产品文档：把已验证能力和限制写清楚；
- prompt 测试：把模型失败样例加入测试。

原则：

> 一个问题如果发生两次，就不只是 bug，而是系统没有学会。

## 7. 输出格式

最终回答使用这个格式：

```text
## 闭环结论
一句话说明这次 VQASee 学到了什么。

## 事实与证据
- ...

## 四角色判断
- 乔布斯：...
- 罗根：...
- 思余：...
- 全麦：...

## 优先级
- P0/P1/P2/P3：...

## 最小实验
- 假设：...
- 改动：...
- 验证：...
- 成功标准：...

## 已沉淀内容
- 更新了哪些规则/测试/文档/skill。

## 下一轮进化
- 1-3 个下一步。
```
