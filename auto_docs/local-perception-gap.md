# 本地感知层：能力与缺口（乔布斯 × 队员）

## 最终结论

用户打开 App 时，本地感知层**能框出人/车、能涂一块可走色、能叠一层车道像素**。四项核心里，**没有一项达到「户外街景敢信 + 实时」**。实验室已经证明几条路能走通，但没翻到 live，或看图没过门。

## 核心四条（live / lab 切开）

1. **障碍物：live 有，不够当路权。** YOLO11n 已 bundle，Mac ~4ms，框人/车。缺口：覆盖召回 0.663、漏 79/701；台阶/路沿不是检测类；框与可走区/引导线没融合成「停在障碍前」。根因：检测当触发器做了，没当通行几何做。

2. **可通行区（分人车）：实验室过了，App 还在混。** mc5 把行人「马路误当人行道」从 0.807 压到 0.096，驾驶道路召回 0.97。shipping 默认 `useMulticlassSegmentation=false`，用户仍吃二值 Fast-SCNN（马路+人行道一块绿）。根因：准的模型 Mac 上 ~586ms/帧，ANE 真机没签字，开关不敢翻。

3. **车道线：能涂像素，画不出司机看见的两条边。** 专用车道分割已 bundle（展示用，Mac ~7ms），CamVid 容差召回 0.98，但画面是色块不是线，用户已否决。UFLDv2 能出折线，但 CULane 城市 hit_rate=0.45、体积 155MB，live `lanePolylineRunner=nil`；CurveLanes 幻象已拒；TwinLiteNet 只在诊断台，12 帧视觉门未过。根因：CamVid 没有车道实例；高速域权盖不住伦敦窄街；像素分割从表示上就不是产品线。

4. **实时性：轻的够快，准的没签字。** YOLO+车道像素便宜；二值分割才是大头（Mac p95 ~170ms）；要角色可走区就得上 mc5（Mac p50 ~586ms）。iPhone ANE 预算从未签字。根因：把 Mac 墙钟和「端上实时」混为一谈，准确度开关被延迟锁死。

## 横断根因（不要再拆成十条）

- **Shipping 和 harness 是两套栈**：记分卡上的好数字大多是离线/开开关跑出来的，不是用户打开 App 看到的。
- **通道没合成一张图**：框、色块、像素车道、中线各画各的；产品要的是占用车道两条边夹一条敢信的引导线，遇障停笔。
