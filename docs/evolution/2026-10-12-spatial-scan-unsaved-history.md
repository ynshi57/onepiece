# 同一空间记录的新增观测不能被历史快照覆盖

用户反馈手机已保存且能在历史找到记录。设备文件检查确认 document 修改时间确实更新，但文件内容仍是旧的 epoch2；恢复诊断另有 epoch3 事件，部分新增照片未被 document 引用。不能据此断言用户具体操作了哪个入口，也不能给孤立照片虚构姿态。

代码中的确定漏洞：历史页只按扫描 ID 判断是否需要保留当前数据。同一 ID 在恢复后追加新 epoch、姿态与恢复事件，再打开该 ID 的旧历史结构，会直接覆盖新增内存。另一个跨异步漏洞是 save 仅按 ID 回写 snapshot，不能保护同 ID 在 await 期间发生的新增变化。

本轮保护以完整 document 对成功提交或载入的快照比较，而非 ID。controller 的 load/start/clear/remove 直接入口阻止未保存替换；同 ID 历史保留本次新增数据。save 回写与导出 URL 回写校验 generation 和实际 document 内容。返回模式保留 ContentView 的持久 controller，停止扫描不替换文档。未保存数据先结束并保存，再开始新扫描或删除。启动失败仅留下状态事件、没有姿态/观测面/照片/定位地图时，允许清除与重新起扫，不让无法保存的空失败状态锁死恢复入口。

存储回归使用真实 SpatialScanStore 文件写入，覆盖 epoch2→epoch3 追加、恢复事件、同 ID 历史覆盖、其他替换入口以及保存 await 期间的同 ID 修改。它们验证数据生命周期，不证明物理定位精度。真机只读确认旧App未运行、原有照片与诊断完整备份后，1014已安装并核实版本；未自动启动App或摄像头。8项最窄模拟器真实文件/ZIP协议回归通过，真机恢复后新增数据的实际保存与导入仍待复测，不能当作A精度验收。未删除孤立照片。

Mac消费协议补充：iOS导出可选携带原始 restoration-diagnostic.json，最多64KiB，并写入现有manifest校验清单。诊断events与已提交document独立；恢复诊断有新epoch但document没有该段时，应报告未持久化，不能把诊断成功当作真实新增轨迹落盘。无诊断的旧导出仍兼容。损坏或超限的附件导出明确失败，原document保留。

实际1014新房间样本已确认新epoch姿态、照片与恢复事件落盘；独立几何精度仍未验收。随后暴露新的跨模块容量不一致：采集允许最多110MiB引用图片、单份地图64MiB、document64MiB，完整原样导出却仅允许127MiB、Mac导入128MiB。真实样本约165MB，保存成功但导出失败，不应归因用户操作，也不应删帧或重新打包冒充手机实际导出。

本轮同步完整ZIP/解压载荷预算256MiB。iOS在写前按每条载荷、30字节local header、46字节central header、两份UTF8文件名和22字节EOCD精确计算，写后核对长度；原document/map/照片各自预算保持。历史载入和恢复前从实际引用图片文件重新统计已用容量，避免重启恢复后仅计新增照片。新版本打开历史即可重新导出已保存样本，用户无需重扫；后续仍需验证手机实际ZIP→Mac导入→真实页面消费，安装与测试不代表这个链路已过。

UI现场反馈：“导出扫描（含照片）”实际是ShareLink，会弹系统分享框，用户容易以为必须另选保存位置才算扫描保存完成。扫描本身已保存在App本机目录，分享只是可选操作。下次App修改把入口改为“分享扫描包”，配“已保存在本机；分享时可选AirDrop或存储到文件”。本轮不为文案单独再次安装，优先验收实际手机ZIP直接导入Mac，用户不用额外上传或选择保存位置。

1015手机实际原ZIP已经读取并直接导入Mac新快照，未重打包：165,267,519字节、183条ZIP成员、179张引用照片；全部manifest SHA、地图SHA、document SHA及导入后落盘文件SHA一致。精确ZIP开销预估与实际文件长度一致。document含epoch2和epoch3、两条恢复事件，诊断29批新平面更新、连续稳定10次，恢复约7.45秒；Mac重新打开快照保持这些证据，缺失事件与缺失恢复段均为空。这个结论是保存与运输数据一致性，不是独立位置/尺寸精度验收。真实页面看图消费由产品负责人另行核对。
