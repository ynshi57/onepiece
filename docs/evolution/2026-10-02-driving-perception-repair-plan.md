# 车载道路感知修复方案与评审

状态：方案经三份独立只读评审修订；规则已落地，本文不代表实现或真机验收完成。

## 问题与证据边界

用户在 iPhone 17 固定车载、约 45 km/h 场景发现：障碍框可见、本车车盖被当作障碍、车道与可行驶区持续缺失，无法查看位置和算法耗时。

以仓库 `311009b` 为代码基线；定位处理还有未提交修改。必须在复现记录中补实际安装构建/模型/配置版本，不能假定手机等于工作区。

- 已证代码事实：`TemporalPerceptionFusion.swift` 在结果年龄 >500 ms 且有优先风险时剥离道路几何；无风险时 `.discard`。
- 新发现：`StreamingViewModel.sendFrame` 对 `.discard` 直接 return，可能使上一次叠层继续显示；没有独立的显示年龄更新机制。
- 已证代码事实：道路加载、执行、解码失败可能只返回 nil；道路耗时仅成功时填写；整体 analyzerFailed 不能代表每个模型健康。
- 已证代码事实：耗时、位置、发布原因没有贯通本地诊断；现有诊断上传依赖远程服务。
- 已证代码事实：障碍后处理未辨别本车，且部分车辆被改名为障碍；原始标签和调整原因未完整保留。
- 待实测：该次路测是否持续超时、是否加载失败/空 mask、朝向和预览裁剪是否错位、车盖原始类别。500 ms 不是已证实的现场唯一根因。

## 乔布斯方向与独立评审

初始方向：作为核心能力缺陷处理。准确度与实时性共同恢复，失败透明、本地可诊断；不能以“安全过滤工作正常”结案。

- 罗根 / `latency_review`：有条件同意。现有年龄截止 worker 完成，遗漏主线程等待/显示；采集时间实际是回调时间。要求完整时间基准、失败计时、显示停滞检测和全样本分母。先等价优化，异步拆模型后必须有独立帧身份。
- 全麦 / `accuracy_review`：有条件同意。先核验输出契约、方向与裁剪。输出按返回顺序猜 DA/lane 有静默互换风险；方向变换后的结果使用原 pixelBuffer 尺寸需对图核实。拒绝把降低处理分辨率直接称为等价优化，因为 rails 参数含像素尺度。
- 思余 / `product_ui_review`：有条件同意。道路和障碍健康分开；本地诊断独立于远程 VQA。原帧与结果同步回看；明确“能看见缺陷”不等于“能力已恢复”。

最终裁决：采纳全部条件。重做静默 500 ms 发布逻辑，同时修复旧图滞留；原始结果保留于有界诊断，实时是否可用由明确状态表示。新显示策略须基于同帧证据与真机预算验证，不能简单改大门槛、无限保留旧图或把过期几何当当前事实。

## 执行任务与接口

### A / P0：证据链与本地诊断

- 主责罗根，思余消费状态，全麦定义模型输出诊断字段。
- 范围：`LocalVisionAnalyzer.swift`、`RoadSurface.swift`、`CoreMLPlatformLoader.swift`、`CameraCapture.swift`、`StreamingViewModel.swift`、`SettingsView.swift`、诊断载体。
- 每帧：session/frame ID、源时间戳及时间基准、回调/入队/开算/阶段结束/UI 发布时刻；无法测实际显示时刻须明确标作发布年龄，不冒充 sensor-to-display。
- 每模型：加载状态、执行状态/原因、成功与失败耗时；TwinLite 分开推理、解码、mask/rails 后处理。记录采集/节流/替换/失败/发布数量。
- 观测链：原始输出摘要 → 几何结果 → 融合结果 → 发布策略与原因；有原图授权时可按同一 frameID 分层回看。
- 位置显示授权、精度、采样时间与有效性；速度未知显示未知，旧位置不能标作当前位置。精确坐标不默认进入导出。
- 无 Mac 可查看；默认有界内存记录，保存/上传图像单独授权。诊断开/关都测耗时，不能让记录本身淹没帧预算。
- 验收：缺模型、推理失败、空 mask、提线失败、超时、断流都可定位；失败也有耗时；不依赖 Qwen。此门通过只算“问题可定位”。

### B / P0：修正发布与显示状态

- 主责罗根，思余负责主屏状态；全麦审查几何时效含义。
- 范围：`TemporalPerceptionFusion.swift`、`StreamingViewModel.swift`、`CameraRiskOverlay.swift`、`AssistanceScreen.swift`。
- 模型观测完整保留，发布选择不覆盖原始结果。道路状态区分准备中、有效、无有效道路、处理延迟、模型不可用；障碍独立报告。
- 移除“500 ms 一到，结果无声消失/旧结果无声滞留”的行为；显示快照即使没有新回调也持续更新年龄和可用性。过期结果可在对应原图查看。
- 只有经过验证的时空对齐才可把历史几何迁移到新帧。显示策略变化本身不算准确度或耗时改善。
- 验收：首帧慢、连续慢、正常转慢、恢复、停止回调、重启会话均有明确行为，且原始结果不丢失、旧帧不冒充新帧。

### C / P1：准确度与耗时两条线并行验证

- 准确度主责全麦：先核验输入方向、输出 schema、预览 aspect-fill 与所有叠层的共享变换。原始 label/confidence/box 与调整后结果同时保留，确认车盖误报来源；自车标定/识别需真实样例，不采用通用底部裁剪。
- 耗时主责罗根：先测量，再优化 MLMultiArray typed/strided 访问、mask/grid 重复采样、重复 rails 提取。保留 dtype、stride、非有限值和阈值边界语义；展示车道与路径的不同筛选条件不可错误合并。
- 若等价优化不足，再评估降低后处理分辨率或拆分调度；分别比较质量和耗时。新调度不得混用不同帧的观测而不标时间。
- 范围：`RoadSurface.swift`、`TwinLiteOccupiedRails.swift`、`LocalPerception.swift`、`CameraCapture.swift` 及坐标变换消费方。
- 验收：等价优化的 mask/有效状态/车道数一致，坐标差异仅限提前声明的数值容差；模型/几何修改需标注真值对照。耗时降低且质量不退化；车盖误报改善时真实近处目标召回不能下降。

### D：同场景验收与失败转向

- 乔布斯负责结项，三位专家分别核查运行数据、画面、模型效果；无需为一次性检查留大量测试代码，但必须保留可核验的结果摘要。
- 同一输入、同一设备、模型/配置、朝向与构建比较修改前后；iPhone 17 Release 测冷启动、稳定运行、热状态，并记录 Debug 差异。
- 数据至少覆盖固定车盖、外部近目标、直道/弯道、静止/移动与无清晰车道；无标注时只能判断运行链路，不能声称准确率达标。
- 质量：道路 IoU、车道匹配与偏差、引导有效率与偏差、车盖误报时长、真实障碍漏报；原始模型/后处理/最终显示分开统计。
- 耗时：排队、各阶段、UI 发布年龄及可测的呈现延迟 p50/p95/p99；统计有效新鲜道路覆盖时长与最长中断，不能只看成功帧 FPS。
- 分母：进入分析的成功/失败/空结果/过期帧全部保留；真值样本中无输出计为漏检；相机节流和待处理槽替换独立记账。
- 先沿用原设计的待验证目标（不是安全承诺）：结果呈现年龄 p95 ≤350 ms、风险首次呈现 p95 ≤250 ms。若只有发布时刻则单独报告该指标；这些目标不能用扩大 freshness 门槛达成。
- 等价优化以输出一致且同机延迟确实改善验收。算法修正的质量门槛在固定样本标注后、A/B 前锁定；同时要求无新增近处真实风险漏检。未经道路实测不能宣布驾驶场景可用。
- 若原始 mask 就错误，转向输入/模型/数据；若原始正确而几何错误，修后处理/坐标；若结果正确但慢，按分段证据优化。每个失败分支均继续推进或写明真实阻塞，不能以增加面板结项。

## 影响面与当前完成边界

涉及本地相机/AR 两个入口、模型加载和输出、融合/叠层、设置诊断及离线 harness。诊断 schema/时间戳如改变，所有消费方必须同步；后端上传保持可选且兼容。安装资源路径与依赖本方案暂不改变，若后续改变则同步安装真源。
