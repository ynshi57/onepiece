# 物品记忆：采集、回放与核心算法详细设计

## 目标

物品记忆的核心不是保存一个坐标，而是重访空间后判断：物品仍在原处、原处未见、物品出现在新位置，或当前证据不足。采集工具为这条算法闭环提供可重放的同帧图像、位姿、内参、跟踪状态和可用深度。采集样本只保存本机，不上传。

## 已实现的采集与回放

入口位于“物品记忆 → 物品记忆选项 → 采集测试样本”。用户选择一个实验计划（未动、移走、移到新位置、遮挡、换相似物、角度/光线变化），名字可选。计划不是逐帧真值。

采集先记录基线。用户按“开始变化”写入单调时间点，变化完成后再按一次；两点之间显示“变化过程·待标注”。每秒最多保存一帧，最多30秒，明确标注“非视频”。后台、相机中断、用户停止、达到上限、写盘失败都会结束采集并保存结束原因。只统计成功写盘的帧；忙碌、无帧、重复帧和写入失败分开计数。

每帧固定来自同一个 `ARFrame`：原始传感器尺寸、实际 JPEG 尺寸、EXIF/界面方向、相机到世界列优先矩阵、原始 3×3 内参、按 JPEG 缩放派生的内参、单调 timestamp、AR tracking 状态。支持 LiDAR 且当前帧提供深度时，保存米制 Float32 little-endian 深度和同尺寸 UInt8 confidence；没有深度显式写原因，不补零。

文件先写照片/深度，再原子更新 JSON manifest。每帧 SHA-256、帧序号和尺寸都会校验；回放遇到缺文件、截断、哈希不符或坏 manifest 明确报错，不使用旧照片静默替代。单段上限30帧/80 MiB，单帧照片或深度上限8 MiB。删除会同时删除照片、深度、confidence 和 manifest。文件使用完整保护并排除备份；模拟器没有真实文件保护语义，真机仍需验证属性。

## 核心算法分层

### 1. 场景对齐：ARKit

ARWorldTracking 将相机运动转换成相机在世界中的位姿；`sceneDepth`（仅支持的 LiDAR 设备）给出相机到画面物体的同步深度。记录时保存物品局部图、周围背景和位置不确定性。重开时加载 `ARWorldMap`，只有 tracking 恢复正常、对应 anchor 找到且持续稳定后才投影旧位置；15 秒失败退回照片。地图恢复只证明空间参考恢复，不证明物品身份或仍在。平面命中是参考位置，可能位于物品后方。

### 2. 物品轮廓：Apple Vision（端侧基线）

用户点击记录照片中的目标。`VNGenerateForegroundInstanceMaskRequest` 提取显著前景实例，生成 mask、归一化外接范围和局部图。它解决“画出哪个物体”，不解决跨天身份、遮挡或消失判断；没有可靠前景时输出失败，不能解释成物品不存在。Apple 文档：[Foreground Instance Mask](https://developer.apple.com/documentation/vision/vngenerateforegroundinstancemaskrequest)。

### 3. 外观匹配：Vision Feature Print（当前保守基线）

对记录局部图和当前候选局部图分别生成 `VNGenerateImageFeaturePrintRequest`，比较 feature distance。当前没有同物/相似物的校准集，因此距离只作为证据，自动状态仍为“无法确认”。匹配必须绑定物品记录、视角质量、原区域是否可见和遮挡证据。

### 4. 连续轮廓传播：SAM 2（离线候选）

SAM 2 支持以点、框或 mask 选取视频目标，并跨视频帧传播 mask。[官方项目](https://ai.meta.com/research/sam2/)。用途是离线建立“移动过程中的轮廓轨迹”对照，帮助判断遮挡、出画和外形变化；它尚未接入 iPhone，不能当作当前端侧实时方案，也不能单独证明物品身份。

### 5. 跨视角匹配：DINOv3（离线候选）

DINOv3 提供高分辨率稠密视觉特征。[官方实现](https://github.com/facebookresearch/dinov3)。用途是和 Vision feature print 比较跨角度局部检索、相似物区分和新位置候选排序。它是候选特征提取器，不是现成的实例身份判定器；模型大小、权重许可、iPhone 延迟和误认率需要先测。

## 状态机与判定

`baseline`：原位置已采集；`transition`：用户标注正在变化；`after`：事件后帧仍需逐帧标注。算法对每次观察输出：`present_at_original`、`not_observed_at_original`、`candidate_at_new_location`、`occluded`、`out_of_view`、`uncertain`，并带观察时间、mask/box、位姿有效性、可见性证据和耗时。

只有同时满足“原区域确实进入视野、空间对齐可信、画面质量足够、遮挡被排除、连续多帧一致、物品证据通过校准阈值”才允许自动给出原处结论。没有分割到、跟踪失败、相似物竞争、短暂遮挡都只能 `uncertain`。自动结果不能把“未观察到”升级成“从房间消失”。用户人工确认只记录当次照片的观察，不冒充自动识别。

移动判断是两阶段：先确认原位置未见，再在当前可见区域生成候选；候选需同时满足外观/轮廓相似、空间/几何一致和连续观察一致。候选不充分时显示“可能在这里”或“无法确认”，不画出确定移动轨迹。

## 评测计划

五件物品、六类事件、每类两次独立采集用于探索；相邻帧不得当作独立样本。按物品和采集会话拆分校准集与测试集。记录错误“仍在”、错误“原处未见”、误认相似物、无法判断比例、mask IoU、定位误差、重定位成功率、p50/p95 判断耗时、功耗和温升。1Hz 采集只能验证稀疏对照和数据链路，不能验收连续跟踪或实时延迟。

下一阶段先做离线回放对照：Vision 基线 → Vision+几何 → SAM 2 传播 → DINOv3/Feature Print 检索；固定输入、独立测试集和失败样例。候选目标是典型日用品变化检出率≥90%、未动/遮挡/换角度误报≤5%、自动结论覆盖≥80%、重新看清后2秒内给结果；这些是实验门槛，不是当前能力声明。低覆盖不能靠全部回答“不确定”伪造高准确。

## 当前完成与阻塞

已完成：本地采集格式、同帧元数据、深度/置信度、原子 manifest、哈希校验、失败计数、时间阶段、历史回放、删除、模拟器合成回放 UI、相关测试。最新采集构建和 22 项单测、3 项室内 UI 测试已通过；模拟器只验证文件/界面，不验证真实 AR/深度/物品。

未完成：真实 iPhone 采集、LiDAR 与普通手机差异、真实轮廓质量、跨启动重定位误差、SAM 2/DINOv3 实测、相似物误认校准、遮挡和新位置自动判断、连续视频实时版本。需要一台真实 iPhone、五件日用品和约20–30分钟首轮采集；数据默认留本机。
