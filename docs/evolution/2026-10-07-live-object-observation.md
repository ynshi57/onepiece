# 物品记忆：连续观察基础，尚未完成物品变化判定

## 用户目标与当前裁决

用户授权第一步：记住杯子，移动手机看回原处；保持不动、遮挡、移走应有不同且正确的反馈。乔布斯负责真实场景验收，不能把上下照片或增加提示文案称为完成。

本轮代码实现了连续空间/视觉取证，但**尚未达到这条目标的完整验收**。没有经过真实标注评测的身份匹配、背景可见性和遮挡逻辑，不能将外观距离、分割失败或深度差直接改成“还在/消失”。

## 具体改动

- `IndoorMemoryController.swift`：画外方向箭头；只保存照片状态；每帧基于当前AR锚点读取高置信度深度邻域；连续几何证据；每秒最多一次串行RGB分割/特征取证。原来的人工比较错误使用原照片像素点，本次改为冻结ARFrame的世界锚点在当前正向照片内投影。
- `IndoorLiveObservation.swift`：独立几何状态与多帧过滤。高置信度3×3邻域至少7点、剔除大离散度；连续不同时间戳且时间足够才发布局部表面线索。无深度、平面参考点、画外、跟踪丢失均不能算消失。
- `IndoorMemoryScreen.swift`：实时观察说明、画外箭头；照片比较明确为辅助入口。仍显示原视角轮廓作为记录参考，**没有宣称已实现真实三维物体轮廓投影**。
- `ContentView.swift`：debug app_status追加几何状态、深度统计、RGB状态/未校准距离/帧时间/耗时；Mac事件页和Codex原样读取，无既有字段更名。只在用户明确共享后发送。
- `DeviceDebugEvidenceBridge.swift`/`DeviceDebugView.swift`：仅显式开启原始样本共享时，发送所选记录的参考照片与target元数据（含轮廓、特征与锚点来源）。开启授权、共享开始、选择记录是消费入口，均同步；保持原有有界上传队列与失败计数。上传失败可重新选择记录触发补传。告知文案同步，关闭不删除已送达资料。
- 单测、UI场景测试：覆盖重复帧、不同几何状态、无效/混合深度、跟踪恢复、照片入口与未确认状态。

成功/失败异步结果共用记录、会话、当前跟踪、当前帧龄及采样帧墙钟年龄验证；结果一秒到期。Vision只保留一个在途任务，不排队堆图；超过两秒显示检查耗时过长并记录证据，不能靠丢慢结果宣称实时性达标。

## 真实限制和剩余必做

1. 当前±15cm、8cm分散度、0.8秒参数仅为实验性几何过滤，未实测校准。杯子移走露出后方桌面可能只有5–12cm差，因而不能用几何一致表示杯子还在。
2. 邻域尚未由当前物品mask约束；视角改变可产生不同表面。未完成背景对齐与“原区域确实可见”的RGB判断。
3. 运行时无sceneDepth设备仍能做RGB取证，但不自动得到遮挡/消失结论。能力依据ARKit运行时支持，不猜机型。
4. 未校准外观距离不转换身份结论；相似杯替换、光照、局部遮挡均需评测。
5. 没有真实“不动换角度/手部遮挡/移走”的原始采样与实例/可见性标注，当前无法完成准确度验收。此前用户42张App屏幕包含UI且原始样本共享关闭，不能包装为已标注算法评测集。

本轮必要继续项：RGB背景/目标区域对齐、可见性融合与物品级多帧状态机；用独立采集会话分别校准/测试；报告误判还在、误判移走、遮挡识别、无法判断比例及端上延迟。**这些仍未完成，不能用补诊断或诚实降级替代能力恢复。**
