# 物品记忆：第一版收尾计划与介绍设计

日期：2026-10-04。用户希望乔布斯和小马说明未完成任务、模式/模型，并制作产品介绍。本文是计划和设计，不是新增能力已完成的声明。

## 乔布斯先定方向

第一版帮助用户在家、书店或咖啡店的桌面附近，手动记录一个物品的历史位置，并在同一空间跟踪会话内转动手机指回。先证明这个体验有用且可信，再扩展跨启动记忆与自动物品识别。

当前代码默认进入室内物品记忆，户外入口在菜单中。室内控制器由 ContentView 持有，切换户外不会主动清除照片列表，但 stop 会失效旧坐标。后台、重新扫描同样保留内存照片、失效坐标；应用进程退出后全部内存记录丢失。照片不上传、不写相册。

## 专家审查与最终裁决

- 罗根：有条件同意。最新代码验证须对应同一构建；18 次只能作为探索，无法记录/超时/失效全部计入，函数刷新耗时不能替代可见延迟。采纳。
- 思余：有条件同意。介绍以记位置、命名、找回为主线；标记本身须有名称和时间；模拟器画面需明确标注。复查实际截图发现标签压缩，P0修复后才能录正式演示。采纳。早期“切户外清除照片”的理解以当前根控制器持有事实纠正。
- 全麦：有条件同意。位置恢复和物品身份分别评测；类别匹配不等于同一物品。采纳。
- 小马：同意以 Apple 原生能力做基线，ARWorldMap 与 Vision 特征比较是后续候选，均需实验。采纳，不预定某个“最强模型”。

乔布斯最终裁决：v0.1 门槛是同会话体验、最终构建与真机验证；v0.2 跨启动恢复、v0.3 身份匹配属于独立增量。未接受在没有实拍证据时使用模拟器录屏冒充空间定位演示。

## 第一版尚未完成的任务卡

### P0-1 位置标签视觉修复

- 主责：思余；配合：罗根。
- 范围：IndoorMemoryScreen 标签测量与布局，必要时同步 visibleRect。
- 事实：已导出的最终 UI fixture 截图，圆点上方标签收缩，名称/时间不可读。
- 设计：圆点固定投影坐标；标签独立获得足够宽高；可见区域由实际控件尺寸推导；避免遮挡或误导到其他位置。
- 交付：同一场景修复前后截图，正常/大字体、横竖屏和长名称覆盖。
- 验收：名称和时间可读、不裁切；文字尺寸不改变圆点落点。真实位置精度另测。
- 状态：待实现，本轮只做介绍与计划，没有重新改动 App。

### P0-2 最新构建和生命周期回归

- 主责：罗根；配合：思余。
- 范围：当前 iOS 变更，含相机串行停止、迟到授权与实际保存 raycast 距离检查。
- 交付：对应源码快照/构建号的 build、相关 XCTest 与 UI 测试结果。
- 验收：室内/户外切换后旧相机、录音不复活；取消命名不留记录；非正常 tracking、过期帧与旧 session 不投影；标签测试补充可读性断言。
- 命令：`bash deploy/ios/test.sh`；窄验证可用 xcodebuild 选择 IndoorMemoryTests 和 IndoorMemoryUITests，设备名以本机可用模拟器为准。
- 阻塞记录：此前自动审批额度失败以及沙箱 CoreSimulator 连接受限；不是已证实的代码编译错误，也不能直接归因于模拟器崩溃。
- 状态：待重跑。本轮读取历史结果，不将其重新描述为最终代码通过。

### P0-3 真机准确度与响应试验

- 主责：全麦、罗根；配合：用户提供真实桌面场景，思余检查实际屏幕，乔布斯裁决是否可试用。
- 输入：同一 iPhone、同一构建，3件物品 × 3观察角度 × 2距离，先做18次探索。
- 设计：记录固定桌面接触点，绕桌返回；用可测量的桌面基准记录定位误差；每次尝试保留成功、无平面、超时、失效原因。
- 失败矩阵：弱纹理、反光、暗光、遮挡镜头、物品移走、后台、切模式、目标在背后。
- 候选门槛：90%尝试误差≤15cm；可见响应p95≤100ms。均为未验证实验目标，需经探索确定合理性并扩样，不能把18次解释为稳定性认证。
- 延迟定义：选择记录到首个有效标记显示，与移动手机时画面/标记更新延迟分别测；用渲染埋点及同步录像核对。现有最近500次刷新耗时/帧龄只属局部诊断。
- 交付：匿名化误差/时延表、失败录像（用户主动同意采集），不提交设备ID或原始私人场景图。
- 状态：缺真机场景观测，未执行。

### P0-4 交付闭环

- 主责：乔布斯；配合：所有角色。
- 范围：CURRENT、roadmap、试用包和介绍材料。
- 设计：同步“代码默认室内入口”与旧文档中户外默认会话的冲突，保留户外能力事实；同会话/内存边界写清。
- 交付：可安装构建、完成后的真实试验记录、60秒实拍演示。
- 验收：新用户能完成首次记位置和找回，并理解这是历史位置。
- 状态：计划中，依赖前三项。本轮已完成说明材料，不发布或分发 App。

## v0.2 跨启动空间恢复设计

主责罗根，思余配合。用户主动选择保存空间，本机保存 ARWorldMap、anchor 与 record 映射、照片和版本信息；明确保存范围、删除与备份策略。

界面状态：正在找回空间；已找回记录位置；暂未找回，可看照片。只有重定位确认后显示旧锚点，失败不能沿用旧坐标。15秒超时可作实验候选默认，仍待实测；超时提供照片、重试或重新扫描。

验证：跨启动、多光照、移动家具、错误房间、损坏地图、删除一致性。恢复地点成功不代表物品仍在；不承诺跨设备恢复。依赖v0.1验证，尚未实现。

## v0.3 物品身份实验设计

主责全麦，小马筛选候选，罗根量耗时，思余呈现证据。先手动框选并保存若干视角裁剪，用 Vision 图像特征做本地基线；基线不足再对比专用视觉特征模型。

独立评测同类相似物品、替换、遮挡、移走、换视角；用误认率、漏认率、拒绝匹配率和耗时选方案。后续状态为确认看见、无法确认、发现于新位置，均附观察时间。不以检测类别直接建立个体身份，不以未检出推断消失。尚未选定生产模型。

## 用户介绍方式

PPT适合团队讨论、离线讲解和归档；浏览器讲解版适合快速浏览。面向终端用户，优先60秒真机视频加可试用版本。这是根据产品的空间交互特点做的选择，不宣称PPT已经过时。

实拍脚本：0–10秒说明桌面任务；10–25秒记录并命名；25–45秒移动手机找回；45–60秒展示历史位置边界或定位中断恢复。当前没有实拍素材，不能用生成图或模拟器视频冒充。

本轮交付9页可编辑PPT和本地浏览器讲解版。截图是实际导出的模拟器 UI fixture，已标示非真实定位，并展示已知标签缺陷。
