# 04 — 走路模式状态机

受众：产品、iOS、后端。

## 状态机

```mermaid
stateDiagram-v2
    [*] --> 空闲
    空闲 --> 连接中: 开始
    连接中 --> 观察中: WebSocket 就绪
    观察中 --> 本地风险: 本地发现人/车/障碍
    观察中 --> 安静观察: 画面稳定且无重要变化
    安静观察 --> 观察中: 下一帧 / 心跳
    本地风险 --> 即时播报: 本地语音/触觉
    即时播报 --> 后端确认: 发送关键帧
    观察中 --> 后端确认: 首帧 / 心跳 / 重要变化
    后端确认 --> 语义结果: Qwen 返回
    语义结果 --> 语义播报: 首次结果 / 风险升高 / 重大变化
    语义结果 --> 安静观察: 无重要变化
    后端确认 --> 恢复中: 超时 / 断线
    恢复中 --> 观察中: 重连 / 下一帧有效
    观察中 --> 空闲: 停止
    安静观察 --> 空闲: 停止
    即时播报 --> 空闲: 停止
    语义播报 --> 空闲: 停止
```

## 关键行为

- 本地风险可以先播，不等 Qwen。
- 稳定帧可以跳过后端，但 Overlay 继续更新。
- Qwen 可能慢，它负责解释，不应该成为第一安全信号。
- 当前限制：切换模式时，正在飞行的旧请求还没有 generation 级取消。

## 必须补的下一步

增加：

```text
modeGeneration / frameGeneration
```

目标：切换模式后，旧结果不能覆盖新模式 UI。
