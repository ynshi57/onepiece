# VQASee Keynote 展示大纲

用途：对外介绍 / 内部评审 / 产品路线沟通。  
风格：Apple Keynote、系统卡片、少文字、大层次、强调安全边界。

## 总体叙事

一句话：

> VQASee 是语音优先的视觉风险辅助系统：先用本地模型快速提醒，再用语义模型解释，并通过真实诊断数据持续变准。

核心边界：

> 它提醒风险，不替代用户观察；它不承诺“可以走/可以开”。

---

## Slide 1 — VQASee 是什么

### 标题

```text
VQASee：视觉风险辅助，不是自动驾驶
```

### 副标题

```text
面向行人、骑行者、驾驶者和注意力可能分散的人，提前提醒风险、边界和不确定性。
```

### 画面布局

- 左侧：一张 iPhone 摄像头画面 mock。
- 画面上有：人/车检测框、黄色风险边界、语音气泡。
- 右侧：三条短句。

### 右侧三条短句

```text
看见风险
即时提醒
持续变准
```

### 页脚安全边界

```text
VQASee 只做辅助提醒，不替代行走、骑行或驾驶判断。
```

### 讲稿

VQASee 不是聊天机器人，也不是自动驾驶。它是在真实移动场景里帮用户多一层视觉提醒：看到可能的人、车、边界和不确定性时，先提醒用户放慢，再用模型解释原因。

## Slide 2 — 用户体验流程

### 标题

```text
先提醒，再解释
```

### 主图

横向 4 步：

```text
持续观察 → 本地风险信号 → 即时语音/触觉 → Qwen 解释
```

### 每步说明

1. 持续观察  
   `iPhone 摄像头和本地模型持续看前方。`

2. 本地风险信号  
   `人、车、自行车、障碍物、遮挡、画面变化。`

3. 即时语音/触觉  
   `“正前方可能有车辆，请放慢。”`

4. Qwen 解释  
   `补充方向、风险原因和不确定性。`

### 视觉建议

- 使用 4 个大圆角卡片；
- 风险信号用橙色；
- Qwen 解释用紫色；
- 用户行动用绿色。

### 讲稿

安全提醒不能等 5 秒。VQASee 的体验顺序是：本地先提醒，语义模型再解释。这样即使 Qwen 慢，用户也能先听到风险提示。

## Slide 3 — 系统分层架构

### 标题

```text
四层架构：快看、慢想、少说、会学
```

### 主图

纵向层级：

```text
体验层       Voice / Haptic / Overlay
反馈策略层   Should speak? What to show?
感知层       Vision / YOLO / OCR / Future Road + Depth
语义层       Qwen / Prompt / Context / Fusion
采集传输层   Camera / Encoding / WebSocket / Backend
学习闭环     Diagnostic Capture / Offline Eval / Regression
```

### 关键文案

```text
本地模型负责快。
Qwen 负责解释。
策略层负责不打扰也不漏风险。
诊断闭环负责持续变准。
```

### 讲稿

我们不是把所有问题丢给一个大模型。VQASee 是分层系统：摄像头采集、本地快速感知、语义解释、语音策略、诊断学习。每一层都能单独优化。

## Slide 4 — 模型职责地图

### 标题

```text
每个模型只做自己擅长的事
```

### 主图

五个模型卡片汇入一个统一信号：

```text
Apple Vision → OCR / 人形基础检测
YOLO11nObject → 人 / 车 / 自行车 / 常见物体
Road Boundary Model → 车道线 / 人行横道 / 路沿 / 可疑通行区域
Depth / LiDAR → 台阶 / 坑洞 / 落差 / 接近风险
Qwen → 解释 / 不确定性 / 语音措辞
```

中间统一结构：

```text
LocalPerceptionSignal
```

### 当前能力标记

- 已实现：Apple Vision、YOLO11nObject、Qwen。
- 原型中：Road Boundary、Depth/LiDAR。

### 讲稿

YOLO 不是道路专家，Qwen 不是几何定位专家。我们把模型拆开：谁负责快，谁负责边界，谁负责深度，谁负责解释。这样才能持续提升准确率。

## Slide 5 — 诊断学习闭环

### 标题

```text
真正变准，靠真实错误闭环
```

### 主图

循环图：

```text
真实使用 → 诊断录制 → 离线分析 → 误检/漏检分类 → 模型改进 → 回归测试 → 新版本
```

### 旁边案例

```text
例：水桶被误检成车辆
```

处理方式：

```text
保存帧 + 模型输出
离线分析误检原因
调整阈值/模型/数据
加入回归样例
```

### 讲稿

漂亮 UI 不能让模型变准。VQASee 必须记录真实误检和漏检，把它们变成评估集和回归测试。一个问题出现两次，就说明系统还没有学会。

## Slide 6 — Road Boundary 路线图

### 标题

```text
从检测框，到可信边界
```

### 三阶段路线

#### 当前

```text
YOLO 检测人/车/自行车
Overlay 显示框和风险标签
```

#### 原型

```text
Mac RoadBoundary Prototype
YOLOPv2 / HybridNets / 语义分割 / Depth
输出边界线、mask、候选走廊
```

#### 未来

```text
真机实时边界
时序稳定
坐标严格对齐
只提示“疑似可通行区域”
```

### 安全底线

```text
不显示“安全路线”
不说“可以走/可以开”
只提示风险、边界和不确定性
```

### 讲稿

我们不会用假线条骗用户。道路边界必须经过模型、深度、时序稳定和坐标对齐验证，才能成为可信功能。

```text

```

### 字体

```text
标题：SF Pro Display / 44-56pt
副标题：SF Pro Text / 24-30pt
正文：SF Pro Text / 18-22pt
注释：14-16pt
```

### 设计原则

- 每页只讲一个观点；
- 不超过 3 行正文；
- 技术词只在需要时出现；
- 当前能力和未来能力必须分色；
- 风险边界必须有页脚提示。
