# Unified Risk Observation：取消用户可见模式

Date: 2026-08-11

## 乔布斯裁决

VQASee 的主体验不再让用户选择“看周围 / 走路 / 详细 / 读文字”等模式。用户层只保留一个核心状态：

> 正在观察风险与障碍。

VQASee 的价值不是“多模式 VQA”，而是帮助人在行走、骑行、驾驶/通勤注意力分散、低视力观察等场景中，更快知道：

- 周围有什么障碍物和危险；
- 近处通行路径是否有台阶、路沿、坑洼、人、车、开门等风险；
- 画面是否看不清；
- 不确定时该放慢、停下或重新确认。

## 安全边界

VQASee 不能替代用户观察或驾驶责任，不能输出驾驶/行走许可：

- 不说“可以走”；
- 不说“可以开”；
- 不给方向盘/车道控制指令；
- 不承诺前方安全。

允许输出：

- “前方疑似有障碍，请放慢确认。”
- “右侧疑似有人/车，请注意观察。”
- “画面不够清楚，我看不清前方。”
- “边界不清楚，请保持人工判断。”

## 产品决定

### 用户层：取消模式

移除主界面模式选择：

- 看周围
- 走路
- 详细
- 读文字

替换为：

- 主按钮：`开始观察` / `停止观察`
- 主状态：`正在观察` / `看不清` / `正在确认` / `已断开`
- 语音问题入口：用户可直接问“这是什么字？”“前面有什么？”

### 系统层：保留自动路由

不能删除内部 mode / route。系统内部仍需按任务路由，以控制延迟、schema 和模型行为：

- `risk_observe`：默认统一风险观察。
- `near_path`：近处通行路径、台阶、路沿、障碍。
- `traffic_risk`：人、车、自行车、开门、路口等动态风险。
- `read_text`：用户问文字或系统检测到文字需求。
- `question`：用户主动语音问题。
- `detail`：用户明确要求更详细解释。

## 为什么这样做

用户在真实场景中不会先思考模式。他们打开 VQASee，只想知道：

> 我周围有什么风险？我现在需要注意什么？

多模式 UI 增加认知负担，也掩盖了产品核心。系统应该替用户判断任务，而不是把模型路由暴露给用户。

## 不做什么

- 不把所有请求合并成一个巨大 prompt。
- 不删除后端 prompt/schema 的任务差异。
- 不让 Qwen 每帧做完整场景描述。
- 不把驾驶风险提醒包装成自动驾驶或导航。
- 不让用户为了读文字去找模式按钮；应由语音问题或自动意图触发。

## 成功指标

- 用户打开 App 到听到第一句有效风险反馈的时间下降。
- 主界面按钮和状态更少、更清楚。
- walking/risk 场景误报和漏报不升高。
- 模型输出仍保持结构化，不因“统一模式”变啰嗦。
- 读文字和用户问题仍能通过语音自然触发。

## 发布验收

- 主界面无模式栏或模式选择按钮。
- 默认启动即进入风险观察路径。
- 内部仍发送可测试的 route/mode 字段到后端。
- UI/语音不出现技术词：route、schema、Qwen、token、ROI。
- 失败状态可见：看不清、模型慢、断开、正在确认。
