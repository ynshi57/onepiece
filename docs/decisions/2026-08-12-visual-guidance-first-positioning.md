# Visual Guidance First：视觉引导优先的产品定位修正

Date: 2026-08-12

## 乔布斯裁决

VQASee 的主体验从“语音优先视觉辅助”修正为：

> 视觉引导优先的风险辅助与通行路径提示产品，语音用于辅助确认、免手提醒和不确定性说明。

VQASee 不再以低视力用户作为唯一或默认产品形态。低视力可访问性仍是一等要求，但普通用户、通勤者、行人、骑行者、驾驶风险提醒用户也必须能在屏幕上直观看到：

- 通行路径 / 引导线；
- 障碍物；
- 风险区域；
- 不确定区域；
- 当前系统是否看得清。

## 为什么修正

单纯语音提醒“请放慢、避让、确认”容易造成认知差异：普通用户需要看到 App 为什么提醒、风险在哪里、建议关注的区域在哪里。视觉引导做得准，语音播报自然可以搭载其上；反过来只靠语音会让用户难以信任。

## 安全边界

视觉引导线不是通行许可，不说：

- 可以走；
- 可以开；
- 安全通过；
- 按这条线走一定没问题。

允许表达：

- 建议关注区域；
- 疑似可通行走廊；
- 被占用/不确定区域；
- 请自行观察并确认。

## 对团队规则的影响

- AGENTS.md：从“语音优先”修正为“视觉引导优先，语音辅助确认”。
- 产品审查 skill：增加通行路径、风险区域、视觉可理解性审查。
- UI skill：引导线、风险区域和视觉层级成为核心审查对象。
- 自进化 skill：新增“呈现得对”，视觉引导质量和语音同等重要。

## 本地层目标

优先建设本地视觉层能力：

1. 通行路径区域识别；
2. 障碍物/人/车/水桶/椅子等占用判断；
3. 画面质量和不确定区域；
4. 引导线和风险区域 overlay；
5. 语音只播报 overlay 的关键变化和不确定性。

## 验收指标

- 普通用户不听语音也能理解主要风险区域；
- 引导线不表达“许可”，只表达“建议关注/疑似通行”；
- 语音和视觉不冲突；
- 误报/漏报能进入诊断报告；
- 低视力用户仍可通过语音/VoiceOver 获得等价风险提示。
