# 0001 VQASee 项目记忆系统

## 背景

VQASee 会持续进行代码修改、模型优化、UI 打磨、产品方案迭代和现场测试。如果所有经验只留在聊天记录里，项目无法形成自闭环，也无法自我进化。

## 决策

建立分层记忆系统：

```text
代码事实        → 代码 / 测试
长期规则        → AGENTS.md
可复用工作流    → .agents/skills/
产品决策        → docs/decisions/
迭代记录        → docs/evolution/
模型经验        → docs/model-lab/
UI 经验         → docs/ui-lab/
性能经验        → docs/performance/
路线图          → docs/roadmap.md
```

## 不选择什么

- 不把所有历史经验塞进 Skill。
- 不只依赖聊天上下文记忆。
- 不把未验证猜测写进 AGENTS.md 成为长期规则。

## 原因

- Skill 应保持短小，负责“怎么做”，不负责存流水账。
- 可验证知识优先变成测试。
- 产品和架构决策需要可追溯。
- 每次现场反馈都应该能进入下一轮进化。

## 后果

收益：

- 项目会积累自己的知识和判断；
- 新一轮 Codex 工作能从已有沉淀继续；
- 重复问题更容易变成测试和规则；
- VQASee 可以形成“观察 → 归因 → 实验 → 验证 → 沉淀”的闭环。

代价：

- 每次较大迭代后需要补充相应文档；
- 需要定期清理过时结论；
- 需要避免文档和代码事实冲突。

## 验证方式

每次完成非平凡改动后，最终回复必须说明：

- 改了哪些文件；
- 跑了哪些验证；
- 本次经验沉淀到哪里；
- 是否新增或更新测试；
- 是否需要更新 AGENTS.md、Skill 或 roadmap。
