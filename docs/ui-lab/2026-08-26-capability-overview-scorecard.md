# 感知能力总览：把涣散的评估收成一页北极星看板

日期：2026-08-26 · 主责：思余（UI/信息架构）· 裁决：乔布斯 · 数据：全麦

## 用户反馈（原话）

> 我就是觉得功能有些涣散，不集中，有好多评估，我也不知道该怎么看，我也不知道目前 iPhone 本地感知的能力达到什么水平？

## 问题归因

诊断台是「一个评估长一个页面」堆出来的：三区状态、引导线、区域 IoU、一致性对比（parity）、案例层……每加一种就多一个页面和一堆并列卡片，**却始终没有一个页面回答那个唯一重要的问题：现在 iPhone 感知到底行不行、是变好还是变差、下一步修哪。**

这是 P1 的**产品闭环 + 信息架构**问题，不是审美问题。对应 AGENTS「内部工具也要产品化」：主流程只该问「现在什么水平」，参数与细节页放到下钻。

## 方案：单一北极星看板 `/diagnostics/ui`

落地页从「hero + 模块网格 + sessions」改为**以能力总览打头**：

1. **一句话定级**：从受门禁保护的 baseline 直接推导 `优/中上/中/偏弱 + 安全/偏保守/冒进`。
2. **3 张核心卡**：看得准（可走区域 IoU/精度/召回）、画得对（引导线命中/覆盖/误差）、安全侧（冒进帧数，绿/红边框）。
3. **变好还是变差**：读 `camvid-ios-report.json` 与 baseline 比 IoU/命中，给 `持平/↑变好/⚠退步`。
4. **下一步修哪**：自动点出最大短板（漏可走/漏线/召回）并指派 owner（全麦）。
5. **下钻收起**：逐帧识别效果、闭环 case、感知配置(OTA)、sessions 都折进 `<details>`。

## 关键实现（`server-vqa/app/diagnostic_api.py`）

- `_capability_snapshot()`：**纯 JSON 函数**，读 `load_baseline("camvid-ios-region"/"camvid-ios-guidance")` 作为「当前受门禁保护的权威水平」，算定级/安全/短板/趋势。可单测。
- baseline 缺失时返回 `available=False + reason`，页面显示「尚无能力基线，去跑一次真身评估」，**不伪造分数**（不可妥协原则 4）。
- 定级规则：IoU≥0.85 优 / ≥0.70 中上 / ≥0.50 中 / else 偏弱；`safe = 区域 false_go==0 且 引导线 false_go==0`；`偏保守 = 召回<0.9 或 漏可走占比>5%`。

## 当前定级（真实数据，701 帧 CamVid，离线，无深度相机分支）

- 看得准：IoU **0.77**、精度 **0.97**、召回 **0.79**、误判可走 **0** 帧、漏可走 **83/701**。
- 画得对：命中 **0.85**、横向误差 **0.09**、覆盖 **0.85**、无路硬画 **0** 帧、漏线 **10/701**。
- 定级：**中上·偏保守但安全**。短板：偏保守（该说能走没说）→ 真机帧微调提召回（Phase 2 已在留出集证明漏报可降到 0）。

## 诚实边界

这是 CamVid 户外街景的**离线**数值、**无深度**相机分支，不是真机体验；室内/雨夜等其它场景不保证一样。页面已用 pill + explain 标注。

## 验证

- `pytest server-vqa/tests` → **240 passed**。
- 新增 4 个测试：总览渲染定级、无 baseline 提示、报告退步→trend down、false_go→unsafe。
