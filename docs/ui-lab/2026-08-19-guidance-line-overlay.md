# UI：逐帧页引导线叠加对照

- 日期：2026-08-19 · 主责：思余
- 位置：诊断台 `/diagnostics/datasets/ios-harness/frames/ui`

## 目标

让用户「看得见」设备预测的可通行路径与真值路径的差距，而不是只看三个状态框或
一堆数字。

## 叠加语义（SVG，viewBox 0..100 拉伸贴合图像）

- **紫色实线 `#bf5af2`**：iPhone 设备预测引导线；带**半透明走廊带**表示 `half_width`。
- **绿色虚线 `#30d158`**：真值可通行引导线（来自 CamVid 语义 mask 中心线）。
- 起点（用户脚下）画小圆点，方便判断线的方向起点。
- 蓝虚线框：检测到的物体（YOLO）；绿/黄/红框：近/左/右区域状态（降为摘要）。

坐标：Vision 归一化（原点左下，y 向上），绘制时翻转 y 贴合 `<img>` 左上原点。

## 关键原则

- `status=insufficient` 或点数不足时**不画线**——降级要以「线消失」呈现，
  绝不用一条假直线糊上去（与后端 `guidance_path` 语义一致）。
- 预测线画在真值线之上，方便直接看偏差；两条线同框对照，`hit/miss` 一眼可辨。
- 图例写进每帧卡片说明文案，避免用户误读颜色。

## 与筛选联动

逐帧页已有的「漏报 / 误阻挡 / 有分歧 / 全对 / 无预测」筛选保留；引导线叠加对
所有筛选桶生效，用户可先跳到「漏报」再逐帧看线级差距。

## 第二轮：线做主角、框降为背景（触发：用户「看到紫线不知道是什么」）

真实反馈:用户看不懂紫线、且觉得绿黄红框「粗糙+重叠+与线打架」。归因——**引导线是
新主信号却画得细、又没进显眼图例**;旧 ROI 色块反而抢视觉。改动(仅 overlay 渲染):

- **线加粗设为主角**:预测线 `width 1.4→2.4`、真值线保持 1.4 虚线;两条线都加**深色
  半透明描边光晕**,在明亮/苍白街景上也看得清。
- **线端加「预测/真值」文字标签**:即使不看图例也能自解释(`paint-order` 加黑描边防糊)。
- **ROI 框弱化为背景**:`fill-opacity 0.14→0.06`、`stroke 0.9→0.5` 且改虚线、文字缩小
  变淡——它是旧的粗粒度分区,降级为背景参考(右侧对照表仍按它算,不丢信息)。
- **显眼图例重写**:头部 callout 分「主信号·引导线」(紫实线=预测路径 / 绿虚线=真值路径,
  越贴合越准)与「辅助·背景」(蓝虚框=检测物体;淡色三区块=旧分区),不再把线的说明
  塞在图片下一行灰字里。

测试:`test_ios_harness_frames_ui_draws_guidance_lines` 更新为断言新图例文案 + 线端
`>预测<`/`>真值<` 标签;顺手修掉一个脆弱断言(`"f2" not in text` 与色值 `#bf5af2`
撞子串),改为精确匹配帧卡标题 `<h2>f2</h2>`。全量 196 passed。

## Backlog（进 roadmap）

- 设备端实时渲染引导线（SwiftUI Path 叠加相机预览）与语音「向左半步」类提示。
- **模型准确度（下一轮，全麦主责）**:收 `over_extension`(线尾越界)、按 driving 视角
  重标定 ROI 阈值/口径降 `risk_miss`——这是用户「我希望是准确的」的正解,UI 清晰化只是
  让问题可见,不替代模型改进。
