# 学习型矢量建图：小范围初筛

用户裁定：主线转向学习型结构识别/恢复，停止靠持续叠加几何规则推进。现有几何保留为观测基线和一致性校验。当前仅完成来源初筛，未运行新模型、未证明泛化或端上可用。

## 两个候选（均为 L2 实验候选，非生产采用）

- [ZeroPlane 官方实现](https://github.com/jcliu0428/ZeroPlane)：单 RGB → 平面实例分割和三维平面，已有预训练模型。先验证是否能找到 ARKit 漏掉的墙面，同时保留家具平面而不误称为墙。官方安装使用 PyTorch CUDA、Detectron2 和编译 MSDeformAttn；尚未验证本机 CPU/Mac 路径。平面输出本身不解决墙/柜语义，不能单独作为完整矢量化方案。
- [SceneScript 官方实现](https://github.com/facebookresearch/scenescript)：半稠密点云 → 结构化墙/门/窗及物体框，直接对应目标输出。公开模型输入为 Aria MPS 半稠密点云，不是任意 RGB 视频即用；官方需要 CUDA/torchsparse、仅测试 Linux，代码/模型为非商业许可。先保留为结构预测路线参考，不能冒充已经适配现有 iPhone 数据。

本机实查：x86_64，PyTorch 已安装，CUDA/MPS 均不可用；因此尚不能按上述官方 GPU 路径执行推理。CPU 可运行性未验证，不断言绝对不支持，也不开展无界移植。

## 本轮裁决与最小实验

乔布斯：必须产出可核对的墙体/开口/轮廓，不以渲染画质或文案修补代替能力。
全麦：有条件同意先验证学习型平面/结构；先用预训练推理，不先训练新网络。RL 暂不作为第一实验，须先明确任务、奖励与可独立验证的数据。
罗根：有条件同意离线验证，先核运行环境和推理时间，不承诺端上实时。
思余：同意在同一照片叠加边界、对应俯视图检查错误；推断与观测需区分。
小马：只核查这两个候选，避免无边界搜集；目前证据不足以宣布模型选型完成。

实验任务接口：全麦主责模型输出，罗根记录运行环境/耗时，思余对照原照片与矢量图，乔布斯裁决。输入沿用已有扫描 RGB、内参与 ARKit 位姿；ARKit 原始平面仅作对照，不充当独立真值。先固定少量覆盖墙/门/家具的照片，补人工图像标注，再运行一个候选；分别核对平面/墙体边界、家具误检、开口保留和多视角一致性。无卷尺时不宣称米制精度；保留失败及完整扫描分母。

退出：同一具体假设两次失败停止；CUDA/权重/许可或数据不适配需显式报告，不开始长期移植支线。未取得可运行环境前不更改安装依赖、默认矢量算法或产品协议。重要认知本次仅沉淀于本卡，暂不把未验证选型写入长期 skill。


补充候选：Grounding DINO tiny（CPU研究，非产品选型）。[官方4.44.2接口](https://huggingface.co/docs/transformers/v4.44.2/en/model_doc/grounding-dino)、[官方模型卡](https://huggingface.co/IDEA-Research/grounding-dino-tiny)。它是文本条件检测，补充YOLO闭词表外的纸箱/画架；不能将给定词表误称完整场景发现。复用现有隔离runtime，无新Python依赖；新模型安装由默认关闭的spatial-grounding profile管理。六图已实际推理，原图框已查看，类别混合、误框与座椅漏检仍存在，未进入可信记忆。

角色学习：产品不得把“床消失但座椅漏掉”当修复；系统保留原始全部查询、失败和耗时；UI明确候选/漏检；模型比较错认与漏认、类别粒度和文本竞争，模型分数不是真值。规则已由现有skill覆盖，不新增长期规则。结果统一记入当日演进记录，不扩写实验日记。

三类对照实证：只给chair/bed/couch，纸箱也被判bed。开放词汇是条件检测，缩窄词表不会自动赋予拒识能力；不可将候选类省略后的输出当事实。后续应评估开放集误报与跨类别混淆，不用正例命中率单独验收。
